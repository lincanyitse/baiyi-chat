## 界面重构

M3.1 的界面是能用的，但读起来累。重做了三层：

### 设计令牌

`app.css` 不再散落硬编码颜色，改成一套令牌：画布/表面/文字三级层次、
单一强调色、四档圆角、一套间距与字号。深色模式跟着
`prefers-color-scheme` 走，不需要单独维护。

刻意不做渐变和重阴影——长时间读正文时它们只是噪音。

### 排版

对话里模型输出几乎全是 Markdown。M3.1 用纯文本渲染，标题、列表、
代码块全压成一坨。引入 `marked`（唯一的新依赖，gzip 后 18KB）：

- **关闭原始 HTML**：模型输出是不可信内容，不能让它注入 `<script>`
- **过滤链接协议**：只放行 http/https/mailto 与站内相对路径，
  挡掉 `javascript:`（含去控制字符后的变形）
- **流式安全**：半截的 ``` 会让 marked 把后文全吞进代码块，
  渲染前统计围栏数并临时补齐

正文样式写在 `markdown.css`——`{@html}` 插入的节点不带 Svelte 作用域
属性，组件内的 `<style>` 命中不了它们。

### 交互

| 项 | M3.1 | 现在 |
| --- | --- | --- |
| 用户消息 | 左对齐带角色标签 | 右对齐胶囊气泡 |
| 助手消息 | 带角色标签 | 头像 + 无气泡正文（更像文档） |
| 正文宽度 | 撑满 | 47rem 阅读宽度 |
| 发送按钮 | 底部文字按钮 | 输入框内圆形图标按钮 |
| 输入框 | 固定高度 | 随内容长高，上限 200px |
| 侧栏 | 平铺列表 | 按今天/7天/更早分组 + 搜索 |
| 空状态 | 「还没有选中会话」 | 欢迎页 + 四个快捷入口 |
| 回到底部 | 无 | 用户上翻时出现浮动按钮 |
| 窄屏 | 侧栏挤压 | 抽屉 + 遮罩 |

输入法组字时的 Enter 必须放行（`e.isComposing`），否则中文候选词
一确认就把半句话发出去。

## 分支树

数据模型不改表——`messages.parent_id` 从 M0 就在，只是从没写入过。

```
u1
 ├ a1
 │  └ u2
 │     └ a2a
 └ a1b            ← 在 u1 下重新生成
    └ u2b
```

### 读取：沿父链回溯

`History` 拆成 `HistoryAt(sessionID, leaf)`：从 leaf 沿 `parent_id`
向上走到根再反转。默认 leaf 是会话里 seq 最大的消息。

缓存键改成 `sessionID@leaf`，不同分支有不同的链。

父节点不存在时（数据损坏、中间节点被删）停在能走到的位置，不报错——
用户至少能看到后半段。

### 写入：追加，不改写

- **普通续聊**：用户消息挂到当前分支末端
- **重新生成**：新回答挂到原回答的父节点下，提问不重复落库
  （`AskOptions.SkipUserMessage`）
- **编辑消息**：新提问挂到原消息的父节点下，成为原消息的兄弟

`AskOptions` 新增 `ParentID`（挂哪）与 `LeafID`（读哪条历史），
三个入口共用同一条 `AskWith` 执行路径——不给分支单开一条，否则
取消、审批、落库会慢慢分叉。

### 迁移

`0007_m3_branch.sql` 把历史消息按 seq 回填成线性链。M0–M2 的数据
parent_id 全是 NULL，语义上本来就是单链，回填后回溯逻辑对老数据
同样成立。

### 前端

消息树接口 `/api/sessions/{id}/tree` 返回每条消息的 `siblings`/`index`。
`Siblings > 1` 时才显示 `← 2/3 →` 切换器。切换目标 leaf 由
`/api/messages/{id}/siblings` 一次给全，只在用户第一次点切换时才请求。

## 跨请求审批

问题的形状：agent 在后台 goroutine 里阻塞等确认，用户点按钮是一个
全新的 HTTP 请求，两者之间没有共享调用栈。

### 挂起表

```go
type ApprovalBroker struct {
    pending  map[string]*pendingApproval  // id -> {req, ch}
    notify   chan struct{}                 // 新审批出现时唤醒 SSE
    approved map[string]bool               // 本会话已放行的工具
}
```

`Request` 生成 id、存表、阻塞在 channel 上；`Decide` 由 HTTP 层写入。
超时与 ctx 取消都转成 `Deny`，**绝不默认放行**。

不落库：单用户本地场景「重启即重开」可接受。`approvals` 表已建好
（0007），留给 M4 做跨进程恢复。

### 三档授权

| 按钮 | 行为 |
| --- | --- |
| 拒绝 | 本次拒绝，`Deny` 不记入会话授权（否则误点会让工具整个会话不可用） |
| 允许一次 | 本次放行 |
| 本会话允许 | 记入 `approved`，后续同工具跳过弹窗 |

危险工具（`RiskDangerous`）不享受会话授权——不可逆操作不该因为
「上次点过允许」就自动执行。

### 从源头禁用仍然是最终手段

`read_only_tools = true` 时把非只读工具从 `session.Service` 的工具
列表里摘掉，模型**根本看不到**，也就不会去调。这是「最小授权」
兜底，与审批策略正交。

### file_write

为了端到端验证审批，新增 `file_write`（`RiskWrite`）。

路径牢笼是硬约束，不是审批能放行的事：`../../etc/passwd`、牢笼外的
绝对路径、经符号链接逃逸，一律拒绝。用 `root + 分隔符` 做前缀比较，
避免 `/data/work-other` 被误判为 `/data/work` 的子路径。

工作目录是 `<数据目录>/workspace`。

## 管理界面

只读诊断视图，不含配置写回（那需要 TOML 序列化 + 热重载，属 F 阶段）。

### 用量面板

`cost.Report(from, to)` 按时间范围聚合 `llm_calls`。不复用现有
`SessionSummary`：那个按 turn_id 集合过滤，而「今天花了多少」是
时间维度的问题，直接走 `created_at` 索引更直接。

按费用降序展示每个模型。未配价格的模型显示「未定价」而不是 `¥0`——
后者会误导用户以为免费。

### 模型服务面板

展示 Provider 的 kind、脱敏后的 base_url、模型能力标签与任务路由。
**绝不返回 api_key**：密钥只存在于环境变量。

`base_url` 只保留 `scheme://host`，隐藏路径——目的是让用户认出
「这是哪个 Provider」，不是暴露内网拓扑。

## 发现的真实缺陷

**1. 续聊时用户消息的 parent_id 为空（分支断裂）。**
普通发消息时没有传 `ParentID`，每条用户消息都成了新的根节点。
表面上 `History` 还工作（默认 leaf 回溯恰好能走通），但一旦重新生成
就会把整条链切碎。修：没有显式 ParentID 时挂到当前分支末端。

**2. Web 渠道从没传 `SessionApproved` / `MarkApproved`。**
「本会话允许」按钮点了等于没点，每次调用都重新弹窗。三个入口
（发送/重新生成/编辑）都缺。修：抽出 `askOptions()` 统一构造。

**3. 工具调用没有落库，`agent.Result.ToolCalls` 是个死字段。**
`Result.ToolCalls` 定义了但从没有任何代码往里写——从初始化到
`finish()` 全程为空。助手消息也只存 thinking + text，用户回看历史时
看不到「查了知识库」「写了文件」，只看到凭空冒出的结论。
修：在 `execute` 里把真正执行过的调用累积到 `t.executed`，
`finish` 带进 `Result`，`session` 落库时一并写入。

**4. `WebConfig` 完全没有默认值。**
`Default()` 里没有 `Web` 字段，`Listen` 是空串。M3.1 靠 `WebURL()`
的兜底显示看起来正常，但 `net.Listen("tcp", "")` 在某些平台会失败。
修：补默认值 `127.0.0.1:8787`。

**5. `/api/providers` 的 routes 直接序列化了 Go 结构体。**
返回 `{"chat":{"Candidates":[...]}}`，前端拿到的是大写字段名。修：转成
`{task: [candidates]}` 的扁平形式。

**6. 只读模式过滤放在 Wire 里。**
配置项 `read_only_tools` 在装配根生效，意味着 REPL 也被它影响——
但 REPL 有自己的终端审批。修：移到 `RunWeb`，按渠道能力决定。

**7. `cost.Report` 的 From/To 没有 json tag。**
返回 `"From"` / `"To"`，与其他字段的小写下划线风格不一致。

**8. 前端侧栏预填「新会话」导致自动命名失效**（M3.1 遗留，本轮修）。
