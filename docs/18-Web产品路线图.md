## 版本策略

**按「用户能做什么」划分版本，不按「实现了多少功能」。**

| 版本 | 一句话 | 判断标准 |
| --- | --- | --- |
| v0.1 可用 | 一个陌生人拿到它能问出第一句话 | 7.1 首次使用旅程走通 |
| v0.2 好用 | 每天用不别扭 | 7.2 日常使用旅程走通 |
| v0.3 完善 | 出问题能自己解决，数据能带走 | 7.3/7.4 旅程走通 |
| v0.4 看得见 | 打开界面就知道能做什么 | 首屏能找到并理解每项能力 |

功能清单是手段，旅程走通才是目标。**一个功能全但旅程断的版本，不如一个功能少但走得通的版本。**

## v0.1 可用

> 目标：从「拿到 exe」到「问出第一句话」不超过五分钟。

### 必须有的

| 项 | 说明 | 状态 |

| 一键启动 | 双击 exe 进 Web 并自动开浏览器；只在首次或端口变化时开页 | ✅ |
| 连通性测试 | 向导第三步会实际查询模型列表，密钥错误当场暴露 | ✅ |
| 错误人话化 | Provider 不可达、认证失败、模型不存在 → 中文说明 + 下一步 | ✅ |
| 失败可重试 | 回答失败后原地重试，不用重打问题 | ✅ |
| 401 自动重登 | 口令会话过期自动回登录页 | ✅ |
| 首次使用闭环 | 7.1 的六步全部走通 | ✅ |

### 已在此前修掉

- 登录页白屏（`isSetup` 未声明）
- 零 Provider 时轮次永久卡住
- 会话过期不重登（后端已返回 401，前端没接）
- `api_key_env` 被硬性校验，导致「先建 Provider 再填密钥」走不通

### 不做

- 数据导出（v0.2）
- 会话归档、后端搜索（v0.2）
- 成本修正（v0.2）

**理由**：v0.1 只要「能问出第一句话」。导出、归档这些是「用久了才需要」的，现在做会拖延可用时间。

类名从样式表挪进了组件字符串，所以 CSS 原文变小、JS 变大，gzip 后合计大约多 1.8 KB。只迁 5 个组件时，原子类还没有在全站复用，体积不会下降。Vite 构建 176 个模块，没有警告。

五个组件的 scoped 样式从约 662 行收到约 12 行（两条保留规则加注释）。五个文件的 diff 是 +209 / −770。

可读性：间距必须写成 `gap-[var(--sp-2)]` 这种任意值，因为根字号是 `--fs-base`（约 15px），Wind 的 rem 刻度对不上 `--sp-*` 和 `--fs-*`。边框、投影、等宽数字也得写任意属性。看单个元素用了哪个令牌更直接，看一整块布局比原来的 scoped 类更吵。真正复用上的快捷类只有 `u-box`、`u-btn-accent`、`u-field-focus`、`u-fs-xs`、`u-fs-sm`。

迁移时踩到的点，后面若继续都还在：

- preflight 是关的。`border` 只设宽度，计算值是 `none`；边框要写成 `[border:1px_solid_var(--border)]`。`border-t` 再加 `border-solid` 会把另外三边也画出来，单边用 `[border-top:1px_solid_var(--border)]`。
- `shadow-md`、`focus:shadow-*`、`tabular-nums` 会展开成未赋值的 `--un-*` 变量，整条声明被浏览器丢掉，计算值变成 `none` 或 `normal`。投影写 `[box-shadow:var(--shadow-md)]`，聚焦环写 `focus:[box-shadow:0_0_0_3px_var(--accent-soft)]`，等宽数字写 `[font-variant-numeric:tabular-nums]`。
- `grid-cols-1` 是 `minmax(0, 1fr)`，原来的单列是 `1fr`。窄屏断点写 `max-[700px]:grid-cols-[1fr]`。
- 过渡拆成原子类后，计算出来的简写和原来的 `border-color 0.15s ease, background 0.15s ease` 对不齐，所以这条留在 scoped 里。
- 原来的 `h3` 规则作用在每一个标题上。只给第一个标题加 flex 类时，第二个标题会变成 `display: block`。
- `[background:none]` 经 lightningcss 变成 `background: 0 0`，计算后的背景色仍是透明，指纹能对上。
- 数据面板两边的备份文件名不同，元素宽度差几个像素。比对时去掉宽高。

这一轮新踩到的点：

- 两条 `max-[]` 写在同一个属性上时，生成的 CSS 把较窄的媒体查询放在前面。390px 同时满足 640 和 900，后写的 900 规则赢了，欢迎页卡片变成两列。改成 `grid-cols-[1fr] min-[641px]:grid-cols-2 min-[901px]:grid-cols-3`。
- `rounded-full` 算出来是 999px。原来 `border-radius: 50%` 的小圆点要写成 `[border-radius:50%]`。
- 元素选择器压过单个类。`.empty p` 盖过了 `.note` 的字号和颜色，空态第二段要按赢的那条来写。
- 类名会串。关于页的状态点同时有 `dot` 和 `ok`，而 `.ok` 是成功提示的 flex 规则，点的计算样式因此是 `display: flex`、`margin-top: 8px`。
- 只在媒体查询里的页签样式，桌面宽度下父级是 `display: none`，子元素的计算样式仍然算得出来。这些类要加 `max-[900px]:`，否则桌面指纹对不上。
- 父级本来是普通块，多写一个 `flex` 会让里面的 `inline-flex` 按 flex item 被块化成 `flex`。
- 原来没有 `:disabled` 的次要按钮，不要加 `disabled:opacity-50`。禁用时透明度仍是 1，光标仍是 pointer。
- 同一元素上不要叠两条都会改写 `border` 简写的任意属性，生成顺序不稳定。分段按钮拆成「第一项」和「后续项」两套完整类名。

## 质量与工程化

2026-11-13 补过一轮测试和分层护栏。数字用跨包统计（`-coverpkg=./internal/...`，按函数百分比等权平均）。单包数字会把「被别的包测到的代码」算成没测。

| 项 | 结果 |
| --- | --- |
| 测试 | `session` 87.1%（93 个函数），`store/sqlite` 91.1%（43），`channel/web` 81.3%（135）。目标分别是 75% / 80% / 65%。快照读取、工具结果往返、编辑与重新生成、续跑、管理接口都有直接断言。详见 [21-测试补强编码计划](./21-测试补强编码计划.md) |

## 优先级判断依据

当多个需求竞争时，按这个顺序：

1. **阻断旅程的**（登录白屏、轮次卡死）—— 最高
2. **让用户困惑的**（技术错误原文、无反馈的等待）—— 高
3. **数据相关的**（导出、备份、成本准确）—— 高（不可逆）
4. **每天都会碰到的**（会话列表、发送、停止）—— 中
5. **偶尔用到的**（配置、技能、知识库）—— 中
6. **锦上添花的**（主题、字号、动画）—— 低

「阻断旅程」与「数据相关」优先于「每天都会碰到」，因为前者是「用不了」，后者只是「不够顺」；而数据丢失是不可逆的。
