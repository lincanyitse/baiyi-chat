## 与计划的关键差异

### 1. 记忆不需要嵌入服务

计划里记忆的情节向量化走 `internal/embed`。实际上**没有用它**：

- 抽取是纯正则规则（微秒级）
- 召回是纯 SQL（`LIKE` + 打分排序）
- `memory_search` 用字面匹配

理由是情节数量在个人规模下只有几百条，向量检索的优势体现不出来，
而依赖嵌入会让「只配了对话模型」的最小配置用不了记忆。等情节上万条
再引入向量，那时 `embeddings` 表已经支持 `owner_kind='episode'`。

### 2. `memory_write` 定为 RiskRead，不是 RiskWrite

计划没写风险等级。实施时先设成 `RiskWrite`，端到端跑起来才发现在
REPL 里每写一条记忆都要按 `y`——「记住我的偏好」变成一个弹窗，
实际使用中极其烦人。

改判据：记忆写入只影响本地记忆库、不产生外部副作用、用户随时可
`/memory rm` 撤销。误记的代价远小于误删文件的代价。

### 3. 唯一索引迫使「先让位再插入」

`idx_facts_active` 限定 `(subject_key, predicate_key)` 只有一条 `active`。
最初的 update 路径「先插新行再标记旧行」直接撞约束。

拆成 `SupersedeAndInsert`：一个事务里先把旧行改成 `superseded`，
再插入新 `active` 行。contradicted 路径不受影响——`disputed` 不占
`active` 唯一索引，直接插入即可。

### 4. 相似度判定需要前缀规则

计划写的是「值精确或 bigram Jaccard ≥ 0.9」。实测「北京」vs「北京市」
的 Jaccard 是 0.5（2 个二元组 / 3 个），判不出相同。

加一条前缀规则：短的一方是长的前缀且差额 ≤ 2 字时判相同。
差额上限是必要的——否则「喜欢」与「喜欢猫和狗」会被合并。

## 核心设计

### 写入管线：四种结局，绝不静默覆盖

```
候选 → 归一化键精确匹配
  ├─ 无同键事实              → inserted
  ├─ 值等价（前缀/Jaccard）   → duplicate（加确认次数，不新增行）
  ├─ 同键不同值 + 新来源更强  → updated（旧行 superseded，事务内完成）
  └─ 同键不同值 + 来源不够强  → contradicted（新行 disputed，旧行保持 active）
```

来源优先级：`explicit 1.0 > turn 0.8 > session_end 0.7 > imported 0.6 > external 0.3`。

「宁可漏记，不可错记」：整条管线零模型调用，同样输入永远得到同样结论。

### 外部内容三层隔离

| 层 | 措施 |
| --- | --- |
| 工具 | `memory_write` 检测到本轮污点（`Taint.IsTainted()`）时，强制把来源降为 `external` |
| 查询 | `AllActiveFacts` SQL 硬过滤 `source_type IN ('explicit','turn','session_end','imported')` |
| 写入器 | `external` 的优先级最低，永远无法覆盖已有事实 |

`TestMemoryNotPollutedByExternalContent` 锁定该行为。

### 召回：热路径零网络

| 通道 | 内容 | 实现 |
| --- | --- | --- |
| 每轮预召回 | 画像卡（≤300 token）+ 条件触发的 top-3 情节 | 纯 SQL |
| 主动检索 | `memory_search` 工具 | 字面匹配 |

情节召回由线索词触发（`上次|之前|那天|继续|还记得` 等）。
无线索词时不召回——问「1+1」时塞三段旧对话毫无帮助。

中文没有词边界，`cueTerms` 生成**汉字二元组**而不是按空格切：
「上次说的容器部署」→ 去掉「上次」→ 切出「容器」「部署」等。

### 画像卡进稳定前缀，情节进当前消息

这是 M2.1 修复的前缀缓存约束的延续：

```
system = 身份 + 工具目录 + 画像卡     ← 稳定，只在 facts 变更时变
当前用户消息 = 情节召回 + RAG + 原文   ← 每轮可变
```

`/context` 实测印证：画像卡在「稳定前缀」段，情节召回在易变区。

## 真实应用验证

用隔离数据目录启动 `baiyi.exe`，走完整 REPL 流程。

**会话 A**：
```
> 请记住：我用 Go 写后端，喜欢简洁的回答
[工具调用: memory_write]
已记住 ✅

> /memory list
  fact_d68a8d9 生效   偏好：用 Go 写后端，喜欢简洁的回答  (确认 2 次)

> /memory card
## 关于用户
- 偏好：用 Go 写后端，喜欢简洁的回答
（29 字，约 19 token）
```

「确认 2 次」说明**规则抽取与模型调用都写入同一事实**，被正确判为
重复而非两条——合并管线按预期工作。

**会话 B**（同一数据库，新会话）：
```
> 你好，帮我写个函数
你好！写什么函数？简单说下需求即可：语言（默认 Go）+ 要实现的功能。

> /context
段             token       配额  说明
身份规则             79     8560  稳定前缀
工具目录            378    16051  稳定前缀
画像卡              18     5350  稳定前缀
情节召回              4     5350
...
```

模型**无需提示**就用了记忆里的语言偏好（「默认 Go」）。画像卡 18 token
在稳定前缀段，情节 4 token 在易变区。

**撤销与溯源**：
```
> /memory why fact_d68a8d9
偏好：用 Go 写后端，喜欢简洁的回答
  状态：生效  来源：explicit（优先级 1.0）
  置信度：0.95  重要性：0.93  确认：2 次
  历史：
    - insert（system）：偏好=…（来源 explicit）
    - confirm（system）：再次确认，来源 explicit

> /memory rm fact_d68a8d9
已撤销：偏好 → 用 Go 写后端，喜欢简洁的回答

> /memory card
画像卡为空（还没有可信的记忆）。
```

## 发现的真实缺陷

**1. `memory_write` 的风险等级错了。**
设为 `RiskWrite` 导致每次记忆写入都要终端确认。改为 `RiskRead`。

**2. 审批器在 stdin 结束时无限重试。**
管道输入读完后再触发审批，`Scan()` 返回 false → 返回 Deny →
模型重试 → 再次审批 → 再次打印提示。日志被同样的提示刷屏。

修复：`terminalApprover` 记住 `inputClosed`，置位后直接拒绝且不再打印。

**3. 「北京」与「北京市」判不出相同。**
见「与计划的关键差异」第 4 条。

**4. 「我是谁？」被抽成身份记忆。**
抽取器只按句式匹配，没排除疑问句。加两道判断：句末问号、句内疑问词
（谁/什么/哪/怎么/如何…）。

**5. 追问线路由切不出中文词。**
线索词过滤后按空格切分，中文整句变成一个词项，匹配不到情节关键词。
改为生成汉字二元组。

**6. `InsertFact` 与唯一索引冲突。**
见「与计划的关键差异」第 3 条。
