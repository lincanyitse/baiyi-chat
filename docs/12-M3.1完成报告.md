## 关键设计

### 1. per-turn 取消：预占 + 真取消

停止按钮需要一个能在 `PrepareTurn` 之后、`AskTurn` 真正开始之前
就生效的机制，否则存在「点了停止但 turn 还没注册」的窗口期。

```go
type turnHandle struct {
    cancel  context.CancelFunc
    stopped bool
}
```

`reserve(turnID)` 先占位（`cancel == nil`），`begin` 拿到 ctx 后填进去。
如果预占期间就被取消，`begin` 立刻返回一个已取消的 ctx。
用结构体而不是装一个空函数，是为了区分「还没开始」与「已经开始且可以取消」。

### 2. `appendMessage` 必须用 `context.WithoutCancel`

用户发完消息立刻点停止，这条消息仍然该留在 transcript 里。
用可取消的 ctx 会让「停止」变成「用户消息丢失」——这是实测中真的踩到的 bug。

### 3. SSE 缓冲放渠道层，不放 session

`session.Service` 的 `StreamCallback` 是一次性的：agent 在单 goroutine
里同步调用，事件不重放。浏览器刷新、网络抖动、多标签页都会错过 delta。

`stream.Log` 是单写多读的环形缓冲（单轮 20000 条 / 8 MiB），
`Append` 永不阻塞订阅者——卡住的浏览器不能拖慢模型输出。

不落库：`NFR-PERF-002` 要求本地排队 <50ms，每个 delta 写一次 SQLite
直接击穿。断线超出缓冲窗口时发 `reset`，前端改拉消息树。

### 4. 「先建后跑」的两条请求

`POST /api/sessions/{id}/turns` 立刻返回 `202 {turn_id}`，生成在后台
goroutine 里跑；`GET /api/turns/{id}/events` 才是 SSE。

这样做的理由：
- 停止按钮需要一个与控制通道解耦的 turn 标识
- 断线重连需要同一轮次能被第二个连接订阅
- 关闭标签页不该中断生成（`runTurn` 用的是 `BaseContext`，不是请求 ctx）

代价是一轮两次请求，可接受。

### 5. 只读工具从源头禁用

M3.1 没有审批弹窗。如果放开写类工具，模型会卡在「需要确认但无人可批」。
在 `bootstrap/wire.go` 里按 `Spec().Risk != tool.RiskRead` 逐个
`SetEnabled(false)`——模型**根本看不到**这些工具，也就不会去调。

配套补了 `Registry.Enabled()`：原来的 `All()` 含被禁用的工具，
而 agent 会把传入的每个工具都下发给模型，用它等于禁用形同虚设。

### 6. `turn_finished` 后以数据库为准

前端 `StreamAssembler` 归并出来的块只用于渲染过程。收到 `turn_finished`
后重新拉一次 `/api/sessions/{id}/messages` 整体替换——断线期间丢过事件
也能对齐到最终状态。`reset` 走同一条路径。

## 发现的真实缺陷

**1. `Approver == nil` 时危险工具静默执行（安全漏洞）。**
`needsApproval` 在 `Approver == nil` 时短路返回「无需审批」，于是
那些本该确认的操作在无人值守渠道里直接执行了。改为：仍然进入审批分支，
`execute` 在无人可问时返回 `Deny` 并把原因告诉模型。

**2. 停止导致用户消息丢失。**
见「关键设计 2」。

**3. `ctx` 被 `:=` 遮蔽，取消状态传不进 `finish` 闭包。**
闭包捕获的是外层未取消的 ctx，于是「用户点停止」被记成「轮次失败」。
改用 `=` 赋值。

**4. 停止时 `History` 失败被当作轮次失败。**
加 `errors.Is(ctx.Err(), context.Canceled)` 判定。

**5. `IsTurnRunning` 在 `PrepareTurn` 后为 false。**
窗口期内点停止会走「轮次已结束」分支。加 `reserve` 预占。

**6. `reserve` 装空函数让 `begin` 误判为已停止。**
改 `turnHandle` 结构。

**7. `History` 对不存在的会话返回空列表而非错误。**
handler 无法区分「会话不存在」与「还没有消息」。`handleMessages`
先 `GetSession` 校验。

**8. 前端预填「新会话」导致首轮自动命名永不触发。**
后端靠「标题为空」判断是否是首轮。前端改为传空标题。

**9. 侧栏标题在自动命名后不刷新。**
轮次结束后补一次 `listSessions()`。失败静默——标题晚一点刷新不影响使用。

**10. `go:embed` 不能引用父目录。**
Vite 的 `build.outDir` 改为直接指向 `internal/channel/web/dist`。
