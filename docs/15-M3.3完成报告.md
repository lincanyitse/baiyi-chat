## 范围

M3.1–M3.2 交付了 Web 骨架与 8 项能力，还剩 5 项。M3.3 补齐它们：

| 阶段 | 交付 | 需求 |
| --- | --- | --- |
| A | 会话级模型切换 | FR-PRV-010 |
| B | 上下文检查器 | FR-UI-008 |
| C | 记忆管理界面 | FR-UI-009 |
| D | 知识库管理界面 | FR-UI-010 |
| E | 附件上传（图片/文档/文件） | FR-UI-004 |

本阶段的本质是「接线 + 视图」：后端能力大多已存在（`memory.Repo`、`rag.Repo`、`jobs.Store`、`context_snapshots` 表），缺的是 Web 层接口与界面。

顺带修正了文档编号：M3 此前只有三份完成报告而没有编码计划，与 M0/M1/M2 的「计划 → 报告」成对规律不一致。现在插入 `11-M3编码计划`，原有报告顺延为 12/13/14。

## 阶段 A：会话级模型切换

### 后端

`Session` 加 `ModelRef` 字段，仓储的三个查询（`CreateSession`/`GetSession`/`ListSessions`）都读它。新增 `UpdateSessionModel`。

`Registry.Lookup(name)` 按名取 Provider——之前只有私有的 `providers` map，`Resolve` 必须走任务路由。

`AskWith` 的选型改为 `resolveForSession`：

```go
if sess.ModelRef == "" {
    return s.reg.Resolve("chat")
}
```

**会话覆盖不参与健康度降级**：用户明确指定了 A，自动降级到 B 会让他以为配置没生效。A 不可用就报错。

### 提交时预检

第一版只在后台跑时才选型，导致「指定了已删除的 provider」要等订阅 SSE 才发现。加 `ValidateSessionModel`，`handleStartTurn` 在 `PrepareTurn` 之前调用，当场返回 400。

### 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `PATCH` | `/api/sessions/{id}` | 新增 `model` 字段，空串恢复跟随路由 |
| `GET` | `/api/models` | 已配置模型的扁平列表 |

`/api/models` 与 `/api/providers/{name}/models` 的区别：后者查的是**服务端有什么**（实测 95 个），前者是**配置里声明过的**（能力信息齐全，才能被选用）。

### 前端

顶栏加 `ModelPicker`，显示「默认 · 模型名」或「会话指定：provider/model」，下拉列出已配置模型与能力标签。

## 阶段 B：上下文检查器

### 补 `prev_snapshot_id`

`context_snapshots` 表有这一列，但 `snapshotSink.SaveSnapshot` 从未写入。补上后「与上一轮对比」变成一次主键查询，不必重新计算。

### 结构化查询

| 方法 | 用途 |
| --- | --- |
| `ContextSnapshotAt(turnID, step)` | 单轮快照，`step=-1` 取最后一步 |
| `ListContextSnapshots(sessionID, limit)` | 会话的快照列表 |
| `DiffContextSnapshots(before, after)` | 逐段 token 差异 |

diff **按 `Segment.Kind` 对齐而不是按位置**：段的顺序与数量可能因裁剪变化，按位置比会得到一堆假差异。输出顺序固定为八段定义顺序，不受 map 迭代随机性影响。

### 接口

| 方法 | 路径 |
| --- | --- |
| `GET` | `/api/sessions/{id}/context` |
| `GET` | `/api/turns/{id}/context?step=` |
| `GET` | `/api/turns/{id}/context/diff` |

### 前端

管理面板「上下文」tab：左侧轮次列表，右侧八段表格（段/中文名/token/配额/占比/裁剪原因），下方可展开的 diff。稳定前缀段带标记。

裁剪原因翻成中文（`drop_rag` → 「丢弃低分知识片段」等），界面不必展示内部枚举。

## 阶段 C：记忆管理

### 拆只读渲染

`ProfileCard` 内部调 `touchFacts` 累加 `access_count`。管理界面反复刷新会污染召回排序——那是「模型多久用到这条事实」的启发值，被人肉浏览污染后就没意义了。

抽出 `renderProfileCard` 返回文本与被注入的 ID，`ProfileCard` 与新增的 `ProfileCardReadOnly` 共享它，后者不调 `touchFacts`。

### 补操作

- `ListAllFacts` —— 含软删除的查询（`ListFacts` 永远排除 deleted，管理页要能看见删过什么）
- `SetFactStatus` —— active/disputed/archived 之间迁移（deleted 必须走 `DeleteFact`，恢复走 `RestoreFact`）
- `RestoreFact` —— 清 `deleted_at` 并回到 active

### 审计链补时间戳

`memory_events` 表有 `created_at`，但 `Repo.Events` 的 SELECT 没读它，`Event` 结构体也没有该字段。补上——审计链没有时间戳是残缺的。

### 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/memory/facts?status=&limit=` | 空 status 含已删除 |
| `PATCH` | `/api/memory/facts/{id}` | `{action: confirm\|dispute\|delete\|restore}` |
| `GET` | `/api/memory/facts/{id}/events` | 审计链 |
| `GET` | `/api/memory/card` | 画像卡（只读） |
| `GET` | `/api/memory/stats` | 计数 |

用 `PATCH` 而非 `DELETE`：撤销是状态变更不是删除，且要能恢复。

### 依赖注入

记忆能力通过 `session.Service` 暴露（新增 `memory_admin.go`），Web 层不直接依赖 `memory` 包——渠道层只认 `Service`。

### 前端

「记忆」tab：五个状态筛选、画像卡只读预览、事实列表、行内操作、审计链展开。

## 阶段 D：知识库管理

### 修 `ChunkCount`

`Document.ChunkCount` 字段存在但 `scanDocument` 从未填充，列表页每个文档都显示 0 片段。新增 `scanDocumentWithCount`，SQL 用子查询计数。

`ListDocuments` 改为委托 `ListDocumentsFiltered(status, offset, limit)`，后者返回总数供分页。

### 接口

| 方法 | 路径 |
| --- | --- |
| `GET` | `/api/kb/documents?status=&offset=&limit=` |
| `POST` | `/api/kb/documents`（multipart） |
| `DELETE` | `/api/kb/documents/{id}` |
| `GET` | `/api/kb/documents/{id}/chunks` |
| `POST` | `/api/kb/search` |
| `GET` | `/api/jobs?kind=` |

### 修 MIME 推断

`Ingester.IngestBytes` 直接采信传入的 MIME，而浏览器与 curl 常送 `application/octet-stream`，导致 Markdown 被当二进制。改为 `mime` 为空或是通用二进制时按扩展名推断。

### 上传响应补片段数

Ingester 返回的 `Document` 不含 `ChunkCount`，上传响应显示 0。改为上传后重查一次。

### 前端

「知识库」tab：状态筛选、上传按钮与拖拽、任务状态条、文档列表、片段展开、检索测试。

向量化是异步的，列表页在有未完成任务时每 3 秒拉一次 `/api/jobs`，全部完成后停止。

## 阶段 E：附件上传

### 范围

三种都支持：

| 类型 | 去向 |
| --- | --- |
| 图片（png/jpeg/gif/webp） | `ImageBlock`，需要模型支持视觉 |
| 文档（md/txt/html/pdf） | 进 RAG + `FileBlock` 附在消息上 |
| 通用文件 | `FileBlock` 透传 |

### 内容寻址存储

`internal/attach` 新包：ID 是 sha256 前 16 位十六进制。同一内容重复上传只落盘一份（实测验证）。元信息（MIME + 原名）存 `.meta` 伴生文件，避免为「这是什么类型」再查一次数据库。

ID 只允许十六进制字符，挡住路径穿越。

### 类型校验

用 `http.DetectContentType` 嗅探真实内容，**不信任扩展名与客户端声明的 Content-Type**。实测：伪装成 `.png` 的文本被识别为 `text/plain` 并归为 document，不会冒充图片。

`DetectContentType` 对文本类统一返回 `text/plain`，markdown 与 html 靠扩展名补判。

### Vision 门控

带图时检查当前模型的 `caps.Vision`，不支持则返回 400 并提示「请在上方切换支持视觉的模型」。

**这是全仓唯一一处消费 `Model.Vision` 的地方**——此前它只被存储与回显。

### 补三个适配器的 `FileBlock`

| 协议 | 格式 |
| --- | --- |
| OpenAI 兼容 | `{"type":"file","file":{"filename":..,"file_data":"data:..."}}` |
| Anthropic | `{"type":"document","source":{"type":"base64",...}}` |
| Responses | `{"type":"input_file","filename":..,"file_data":"data:..."}` |

### 修 Responses 的静默丢图

`responses.go` 遇到二进制图片直接 `continue`——用户以为发出去了，实际模型什么也没收到，**比报错更糟**。改为转 base64 data URI。

### 前端

输入框左侧加附件按钮 + 拖拽上传。已选附件显示缩略图（图片）或文件图标，可移除。

## 发现的真实缺陷

**1. `prev_snapshot_id` 从未写入。**
列在 `0003` 就建好了，`snapshotSink` 的 INSERT 却一直没带它。导致跨轮对比只能重新计算或放弃。

**2. `Document.ChunkCount` 恒为 0。**
字段存在、`ChunkCount()` 方法也存在，但 `scanDocument` 没读。列表页每个文档都显示「0 片段」。

**3. `Event.CreatedAt` 缺失。**
`memory_events.created_at` 有值，`Repo.Events` 的 SELECT 没读，结构体也没字段。审计链没有时间戳。

补上字段后还踩了第二个坑：`LogEvent` 写的是 `UnixMilli`，`Events` 却用 `time.Unix(created, 0)` 按秒解释，读出来的时间落在 1970 年。**补字段不等于补对了**——单位约定必须和写入侧对齐。

**4. `IngestBytes` 采信错误 MIME。**
浏览器送 `application/octet-stream` 时，Markdown 被当二进制处理。

**5. Responses 适配器静默丢弃二进制图片。**
用户以为图片发出去了，模型什么也没收到。

**6. 会话级模型的错误反馈太晚。**
第一版只在后台选型，指定了坏模型要等订阅 SSE 才发现。改为提交时预检。

**7. 上传响应缺片段数。**
Ingester 的返回值不含 `ChunkCount`，上传返回 0 而列表页正确——两处不一致。

## 代码清理（四角度审查）

M3.3 收尾时对全部 M3 未提交改动做了一轮「复用 / 简化 / 效率 / 修改深度」审查，四个方向并行。修掉的：

| 项 | 问题 | 处理 |
| --- | --- | --- |
| **审计链时间单位** | `Events` 按秒解释 `UnixMilli` 写入的值，时间落在 1970 年 | 改 `time.UnixMilli`，补回归测试 |
| **续跑双份实现** | `ResumeTurn` 与 `ResumeTurnWith` 逐行复制，前者曾因漏传 Approver 出过 bug | 前者一行委托后者 |
| **分支计划算两遍** | Web 先 `Regenerate`（查 2 条消息）再 `RegenerateWith`（再查一遍） | `Regenerate`/`EditMessage` 返回 `branchPlan`，新增 `RunBranchTurn` 复用 |
| **段名映射两份** | Web 与 REPL 各一份八段中文名，且已漂移（「知识片段」vs「RAG」） | 收进 `contextx`，`SegmentKind.Label()` / `TrimReason.Label()` |
| **上传样板两份** | 知识库与附件两个 handler 各写一遍 multipart 解析与四道错误分支 | 抽 `readUpload` |
| **前端上传两份** | `uploadDocument`/`uploadAttachment` 逐字相同 | 抽 `uploadFile` |
| **时间格式化三份** | 三个面板各写一份 `fmtTime`，其中两份逐字相同 | 新 `lib/format.js` |
| **`RebuildEmbeddings` N+1** | 每批 200 个 chunk 逐条查库 | 用已有的 `ChunksByIDs` |
| **`Stats` 五次串行** | 管理面板刷新走 5 次往返 | 合并成一条 SELECT |
| **情节访问逐条写** | 与同文件 `TouchFacts` 的批量理由自相矛盾 | 新增 `TouchEpisodes` 批量版 |
| **Vision 门控静默放行** | 解析不出模型时跳过检查，图片原样发给不支持的模型 | 改为拒绝并说明原因 |
| **附件入库阻塞请求** | 用 `context.Background()`，请求取消/关停时跑不完 | 改用请求 ctx |
| **附件元信息换行拼接** | 文件名含换行会切坏 `.meta` | 改 JSON |
| **`IsLoopback` 手工切字符串** | `[::1]:8787` 被切成 `[::1`，非回环警告误报 | 改 `net.SplitHostPort` + `IsLoopback` |
| **历史缓存无上限** | 每看一个分支多一个 `sessionID@leaf` 键，只增不减 | 每会话最多 4 个视图，超限淘汰 |
| **`buildFinal` 大半无效载荷** | 构造完整 DTO 但前端只读 `status`/`error` | 只发两个字段，删掉不再使用的 `TurnDTO` |
| **死代码** | `runTurn`、`approver()`、`s.turns == nil` 三处检查、`ErrCodeConflict` | 删除 |
| **重复查询** | `ContextSnapshotByID` 查两次；`handleListDocuments` 手工解析 offset | 一次查完 / 复用 `queryInt` |
| **启动重复拉列表** | `auth === null` 时先拉一次，状态回来再拉一次 | 等认证状态确定 |

**未采纳**（记录理由）：
