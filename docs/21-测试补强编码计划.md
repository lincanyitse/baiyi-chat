## 目标

补上跨包统计后仍然是 0% 的路径，让「对话编排、快照读取、管理接口」有直接断言，而不是只靠端到端碰巧走到。

**一句话验收**：`go test ./...`、`go vet ./...`、`scripts/check-layering.sh` 全绿；下文「缺口」里列出的函数不再是 0%（明确排除的除外）；跨包函数平均覆盖率 `session` ≥ 75%、`store/sqlite` ≥ 80%、`channel/web` ≥ 65%。达不到的如实写在文末，不改目标。

覆盖率一律用 `-coverpkg=./internal/...` 跨包统计。单包数字会把「被别的包测到的代码」算成没测，曾经把 `session` 误报成 30%（跨包后约 60%）。

## 范围

**做**：

- `store/sqlite`：上下文快照读写、工具结果幂等、轮次列表、消息搜索、摘要、会话级模型、软删除、`OutputStore`
- `session`：快照读取与 `LatestContext`、编辑与重新生成、续跑、搜索与列表、热替换注册表、标题生成、摘要、模型能力查询
- `channel/web`：仍为 0% 的 HTTP 处理函数。每个至少覆盖成功、未装配、非法参数三条里适用的那些
- `bootstrap`：`memoryAdminOf` 必须返回真正的 nil 接口
- `Makefile` 增加 `cover` 目标，按包打印跨包覆盖率

**不做**：

- `ListenAndServe`、`sweepLoop`：要占端口并跑定时循环，断言不稳定，排除
- `spaHandler`：依赖已构建的前端产物，不属于本计划
- 前端组件测试、桌面分支 `feature/desktop-m4`
- 为了凑覆盖率而 mock 掉真实的协议适配器。假的是上游 HTTP，适配器走真的

## 缺口（开工时的跨包统计）

上下文快照整条读取没测过：`ContextSnapshotAt`、`ContextSnapshotByID`、`ListContextSnapshots`、`LatestContext`，以及 store 侧的 `GetContextSnapshot`、`GetContextSnapshotByID`、`ListContextSnapshots`、`scanContextSnapshot`。这是把 SQL 从 `session` 搬进 `Repository` 之后留下的。

`store/sqlite` 另外还有：`SearchMessages`、`ListTurns`、`SaveSummary`、`output_store.go` 全部方法。

`session`：`EditMessage`、`RegenerateWith`、`ResumeTurn`、`ResumeTurnWith`、`ResumableTurn`、`SearchMessages`、`ListSessions`、`SetRegistry`、`SessionSummary`、`Summarize`、`maybeCompress`、`GenerateTitle`、`SessionModel`、`ModelCapabilities`、`ListModels`。

`channel/web` 约 50 个处理函数为 0%，集中在知识库、记忆、导出、附件、诊断、上下文、插件、分支、审批。

## 拆分

### 批次 1：store

新建测试，不改生产代码。断言包括：

- `SaveSnapshot` 的 `prev_snapshot_id` 链、`step < 0` 取最后一步、不存在时 `errors.Is(..., session.ErrNotFound)`、列表按会话隔离、默认上限、坏 JSON 报解析错误
- `SaveToolResult` / `GetToolResult`：`IsError` 保真、缺失时 `ok=false` 且 `err=nil`、重复写入不覆盖
- `ListTurns`、`SearchMessages`（含 LIKE 转义）、`SaveSummary` / `LoadSummary`、`UpdateSessionModel`、`DeleteSession`、`TouchSession`、`GetMessage`
- `OutputStore` 的保存、按偏移读取、删除、GC、快照写入与读取

### 批次 2：session

新建 `internal/testutil/upstream`：可脚本化的 OpenAI 兼容 SSE 服务，外加 `/v1/models`。`channel/web` 里的 `fakeUpstream` 在 `_test.go`，别的包用不了。

用它跑真实轮次，覆盖快照读取、编辑、重新生成、续跑、搜索、`SetRegistry`、标题与摘要。

### 批次 3：web

复用 `newTestEnv`。知识库、记忆、导出、附件用真实的仓储与文件目录，不用假接口冒充成功。未装配时断言 404 或「未启用」。非法参数断言 400。诊断包断言密钥行被替换成 `***`。

### 批次 4：bootstrap

`memoryAdminOf(nil)` 与「有 Hooks 但没有 Repo」都必须是 nil 接口，不能是装了 nil 指针的非 nil 接口。装配后 `ListFacts` 能调用。

## 验收命令

```bash
go test ./...
go vet ./...
bash scripts/check-layering.sh
make cover
```

测试不得访问外网，不得读取真实密钥或 `%APPDATA%\baiyi`。

## 结果（2026-11-13）

跨包函数平均（`go test -coverpkg=./internal/... -coverprofile=coverage.txt ./internal/...`，再按函数百分比等权平均）：

| 包 | 目标 | 实测 | 函数数 |
| --- | --- | --- | --- |
| `internal/session` | ≥ 75% | 87.1% | 93 |
| `internal/store/sqlite` | ≥ 80% | 91.1% | 43 |
| `internal/channel/web` | ≥ 65% | 81.3% | 135 |

缺口清单里的函数都不再是 0%。仍然是 0%、并且本计划明确不测的：

- `ListenAndServe`、`sweepLoop`：要占端口并跑定时循环
- `spaHandler`、`Static`：依赖已经构建进二进制的前端产物

`GetTurn` 原先在找不到轮次时返回裸的 `sql.ErrNoRows`，Web 把它映射成 500。这次收成 `session.ErrNotFound`，缺轮次的续跑请求返回 404。

`go test ./...`、`go vet ./...`、`scripts/check-layering.sh` 已通过。分层检查仍警告 `export` 直接依赖 `session`，这是已知的待治理项，不是这次引入的。
