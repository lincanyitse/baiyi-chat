# M0 编码计划 — 地基与单发对话

> 状态：待确认
> 上游文档：[架构纲要](../docs/03-架构纲要.md) · [需求文档 §8.1](../docs/02-需求文档.md#81-m0-地基与单发对话)
> 前置条件：无（可立即开工）

## 目标

把契约根立起来，跑通两家 Provider（OpenAI 兼容 + Anthropic 原生）的真实流式对话。

**一句话验收**：在 REPL 里连续多轮对话 DeepSeek 与 Claude，流式正常；进程重启后会话可续；每轮打印 token 与费用；FTS5 中文冒烟结论写入 ADR-0007；`CGO_ENABLED=0` 构建通过。

## 范围

**做**：
- 包骨架（`internal/` 目录结构）与依赖方向 lint
- `infra`：配置、日志、ID、SQLite 连接与迁移
- `llm` 契约根：消息模型、流式事件、能力清单、错误类型
- 两个 Provider 适配器：OpenAI 兼容、Anthropic 原生
- 本地模型接入（按 OpenAI 兼容，超时放大、并发压低）
- 最小 REPL（多轮、流式、`/exit`）
- transcript 落库（`sessions` / `messages` / `turns`）
- 最简成本记账（`llm_calls` / `prices`）
- FTS5 中文检索冒烟（应用层 bigram 方案验证）

**不做**（留给后续里程碑，见到请求不心软）：
- Agent Loop / 状态机 / 工具（M1）
- 审批、上下文组装器、快照（M1）
- 记忆、RAG（M2）
- SSE / Web（M3）
- `prices` 表 M0 只做只读：价格手填进配置或表里，不做管理界面

## 包依赖与实现顺序

按架构纲要 §2.3 的依赖方向，自底向上实现，每个阶段结束可编译、可测：

```
阶段 1        阶段 2         阶段 3          阶段 4         阶段 5
infra    →   llm 契约根  →  provider     →  session      →  cmd/baiyi
（配置/日志/  （消息/事件/    （openaicompat+  （SQLite 落库）  （REPL 装配）
 SQLite/迁移） 错误/能力清单）  anthropic 适配）      ↑
                                            阶段 4.5: cost 记账
                                     （llm_calls / prices，挂在 provider 调用后）
```

## 阶段明细

### 阶段 0：包骨架与 lint 约束（0.5 天）

- 建目录：`cmd/baiyi/`、`internal/{infra,llm,provider,session,cost,store,bootstrap}`
- 添加 `depguard` 或等价 lint 配置，先固化两条：`llm` 不 import 内部包（标准库除外）；`infra` 不 import 任何 `internal/*`
- `scratch/` 里先跑 `modernc.org/sqlite` + FTS5 可用性验证（冒烟前哨），结论进 ADR-0007 草稿

**产物**：可编译的空骨架；FTS5 前哨结论。

### 阶段 1：infra（1 天）

按架构纲要 §15.1 的选型，只引入 M0 必需的依赖：

| 组件 | 选型 | 文件 |
| --- | --- | --- |
| 配置 | `koanf` v2 + TOML + env 覆盖 | `internal/infra/config/` |
| 日志 | `log/slog` + `tint`（控制台）+ JSON 文件（M0 可先不做轮转，FR-OPS-005 完整验收在 M0 收尾） | `internal/infra/logx/` |
| ID | `google/uuid`（UUIDv7） | `internal/infra/idgen/` |
| SQLite | `modernc.org/sqlite`，WAL、`busy_timeout=5000`、`foreign_keys=ON` | `internal/infra/sqlite/` |
| 迁移 | 自研约 100 行：`go:embed` SQL + `PRAGMA user_version` + 迁移前备份 | `internal/infra/sqlite/migrate.go` |

M0 首批迁移只建 5 张表（架构纲要 §11.1）：

```sql
sessions   (id, title, preset_id, created_at, updated_at, archived_at)
messages   (id, session_id, seq, parent_id, role, content_json, trust, pinned, compacted, created_at)
turns      (id, session_id, status, error_json, started_at, ended_at)
llm_calls  (id, turn_id, step, provider, model, purpose, input_tokens, output_tokens,
            cached_tokens, reasoning_tokens, latency_ms, ttft_ms, price_version, error_kind)
prices     (provider, model, currency, in, out, cached, effective_from)
```

**产物**：`config.Load()` / `logx.New()` / `idgen.New()` / `sqlite.Open()+Migrate()`，各自带单元测试。

### 阶段 2：llm 契约根（1 天）

这是全系统最重要的纯数据包，写完短期内不再动：

- `message.go`：`Message` / `Block`（Text / Image / ToolUse / ToolResult / Thinking / Citation）/ `MessageMeta`（含 `Trust` / `ParentID`）
- `stream.go`：归一化事件（`Start` / `BlockStart` / `TextDelta` / `ThinkingDelta` / `BlockStop` / `Usage` / `Stop` / `Error`），满足架构纲要 §3.3 的七条契约
- `capability.go`：能力清单 struct（M0 只用其中 5 个字段：`ContextWindow` / `MaxOutput` / `Tools` / `Vision` / `PrefixCache`）
- `errors.go`：`Error{Kind, HTTPStatus, VendorCode, Message, RetryAfter}`，Kind 枚举按 §4.6
- `provider.go`：`Provider` 接口（`Stream` / `CountTokens` / `Capabilities` / `Health`）

M0 阶段 `ToolUse` / `ToolResult` block **只定义不使用**——它们在类型系统里占位，保证 M1 加工具时不动消息模型。

**产物**：`llm` 包全量类型 + 契约测试（事件序列合法性断言可先写成测试辅助函数）。

### 阶段 3：Provider 适配器（2–3 天，M0 最大风险区）

两个适配器，外加一个注册表：

| 文件 | 内容 |
| --- | --- |
| `provider/registry.go` | 名称 → 构造器；模型元信息（能力覆盖 + 价格）从配置读入 |
| `provider/openaicompat/` | `/chat/completions` 流式；SSE 行解析；`choices[].delta` 增量；`tool_calls[].index` 分片累加（M0 只解析不执行，逻辑先行） |
| `provider/anthropic/` | `/v1/messages` 流式；具名事件；`input_json_delta` 缓冲；`cache_control` 断点（M0 先打一个在 system 上） |

实现要点（来自架构纲要 §3.3、§4.4、§10.4）：

- SSE 解析器独立成小模块（`sseparse.go`），两家共用，`bufio.Scanner` 按行 + `event:`/`data:` 分帧
- OpenAI 侧必须处理：`include_usage` 显式开启；`id`/`name` 首片缺失或每片重发都要容忍；最后空 choices 分片带 usage
- Anthropic 侧必须处理：`signature` 原样带回；`ping` 事件忽略；`error` 事件中途到达要转成 `ErrorEvent` 并终止
- 两家的 usage 字段名不同，映射到统一 `Usage`
- 每个适配器配「录制回放」测试：手工抓一次真实 SSE 响应存为 golden 文件，测试时回放（M1 补 fuzz）
- 超时：连接 10s / 首 token 30s / 整体 120s

**产物**：`go test ./internal/provider/...` 用录制流全绿；用真实 key 手工冒烟通过。

### 阶段 4：session 与 cost（1 天）

- `internal/session/repo.go`：`SessionRepo` / `MessageRepo` / `TurnRepo` 接口（消费方定义）+ `store/sqlite/` 实现
- `internal/session/service.go`：`StartSession` / `AppendMessage` / `OpenTurn` / `CloseTurn` / `ListSessions`
- `internal/cost/ledger.go`：`Record(provider, model, usage, latency, ttft, err)` → `llm_calls`；`Price(provider, model)` 查 `prices` 表（M0 无价格数据时返回「未知价格」，记录仍写入）
- transcript 落库时机：用户消息进轮即写 `received`；助手消息流结束时写完整 content blocks；`llm_calls` 在每次调用结束时写

**产物**：session 层单测（内存 SQLite）；重启后会话可续的集成测试。

### 阶段 5：REPL 与装配（1 天）

- `internal/bootstrap/wire.go`：唯一装配根。读配置 → 打开数据库 → 构造 providers → 构造 session 服务 → 构造 REPL
- `cmd/baiyi/main.go`：读 `main.version` / `main.commit`（Makefile 的 ldflags 已预留这两个变量）
- `internal/channel/repl/`：
  - 读入 → 显示流式输出（按事件渲染，Thinking 显示为灰色前缀）
  - 命令：`/exit` 退出、`/sessions` 列表、`/switch <id>` 切换、`/new` 新会话、`/model` 查看当前模型
  - 每轮结束打印一行：`[tokens: in 1234 out 567 cached 0 | $0.0023 | 1.4s]`
- 数据目录：`%APPDATA%\baiyi`，可被 `BAIYI_DATA_DIR` 覆盖

**产物**：`make build` 出 `bin/baiyi.exe`，双击可跑（REPL 不需要终端以外的东西）。

### 阶段 6：FTS5 中文冒烟 + M0 收尾（0.5–1 天）

- 冒烟脚本放 `scratch/fts5-smoke/`：
  1. 建 FTS5 表（`unicode61` 默认分词）+ bigram 影子列，各灌 200 条中文样本
  2. 对比查询：「白泽助手」「会议纪要」「第三季度报告」等真实感查询的命中与耗时
  3. 结论三选一：A（bigram 可用）/ C（退化为 LIKE + 向量兜底）/ 其他
- 把结论写进 `docs/adr/ADR-0007`，并在需求文档 OQ-001 打勾
- M0 验收清单逐项过一遍（下表），更新需求文档 §8.1 状态

**产物**：ADR-0007 定稿；M0 验收记录。

## 风险与预案

| 风险 | 概率 | 预案 |
| --- | --- | --- |
| OpenAI 兼容系的 tool_call 分片格式比预期更乱 | 高 | M0 只解析不执行，解析器独立成包，M1 再扩展；录制回放保底 |
| `modernc.org/sqlite` 与 `mattn` 行为差异（如 FTS5 编译开关） | 中 | 阶段 0 就做前哨验证，不行换 `mattn`（需装 mingw，代价写进 ADR） |
| Anthropic 思考块签名处理出错导致 400 | 中 | M0 先在配置里默认关闭 thinking；契约里保留字段 |
| 价格表没有数据来源 | 低 | M0 手填 2–3 家主用模型；`Price()` 查不到返回未知并继续 |
| 阶段 3 工期失控 | 中 | 适配器是 M0 唯一「有外部不确定性」的部分；先做 OpenAI 兼容（DeepSeek 验证），Anthropic 随后；必要时先砍「录制回放」到 1 个样本 |

## 工期与粒度

总计约 **6–8 个工作日**。每阶段一个自然提交点，提交信息用 `M0-n: <内容>` 前缀。

开工前需要你确认三件事：

1. **API keys**：DeepSeek 与 Anthropic 的 key 我需要你放到环境变量（`DEEPSEEK_API_KEY` / `ANTHROPIC_API_KEY`），我不经手明文。
2. **Ollama**：本机是否已装、模型是否已拉取？没有也不阻塞，验收项 3 可以最后验。
3. **配置初值**：默认对话模型先用 DeepSeek（便宜、OpenAI 兼容最标准），还是你另有偏好？（对应需求文档 OQ-002）
