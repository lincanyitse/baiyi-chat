> 文档编号：BY-DOC-19

> 上游：[17-Web产品规格](./17-Web产品规格.md) §9 · [18-Web产品路线图](./18-Web产品路线图.md) v0.2

## 1. 为什么现在做

刚做完的 API Key 加密存储解决了一个断层：**普通用户没有终端，配不了模型**。
技能与 MCP 是同一个断层的另外两半：

| 能力 | 现在怎么用 | 谁能用 |
| --- | --- | --- |
| 模型服务 | ~~改 config.toml + 设环境变量~~ → 已改为页面配置 | 所有人 |
| 技能 | 往 `<数据目录>/skills/` 扔一个 `SKILL.md` 目录 | 知道目录在哪的人 |
| MCP | 在 `config.toml` 手写 `[[mcp]]` 段，重启 | 会写 TOML 的人 |

产品断言是「打开就能用」。技能和 MCP 是白泽区别于普通聊天客户端的地方——
**如果它们只能靠手写文件启用，这个区别只对开发者成立**。

v0.2 的主题是「每天用不别扭」，而「加一个能力要重启 + 手改配置」正是最别扭的一种。

## 2. 现状核查

### 2.1 技能：有内核，无入口

| 项 | 位置 | 状态 |
| --- | --- | --- |
| 目录扫描与热加载 | `skill.Catalog.Refresh` | ✅ 内容哈希比对，无需 fsnotify |
| 渐进披露（L0 目录 / L1 正文 / L2 参考） | `skill.Load` + `load_skill` 工具 | ✅ |
| 确定性触发词 | `Catalog.MatchTriggers` | ✅ |
| 启用/禁用 | `Catalog.SetEnabled` | ⚠️ **只改内存，重启即丢** |
| Web 接口 | — | ❌ 无 |
| 界面 | — | ❌ 无 |

`SetEnabled` 的注释说「供管理界面使用」，但管理界面不存在，且它不落盘——
**这是本次要补的第一件事**。

### 2.2 MCP：只能启动时连

| 项 | 位置 | 状态 |
| --- | --- | --- |
| stdio / http 传输 | `mcp.Client.Connect` | ✅ |
| 工具适配 + 外部内容污点标记 | `mcp.Tool` | ✅ |
| 白名单 `allowed_tools` | `Client.discoverTools` | ✅ |
| 连接失败容错 | `connectMCP` | ✅ 单个失败只跳过 |
| 连接状态查询 | `Client.Healthy` 声明了但**没有方法体** | ❌ |
| 重连 | — | ❌ |
| 增删改 server | 手写 TOML + 重启 | ❌ |
| Web 接口 | — | ❌ |
| 界面 | — | ❌ |

**发现的问题**：
1. `internal/mcp/client.go:148` 的注释 `// Healthy 报告连接状态。` 后面直接跟了
   `Close`——`Healthy` 方法根本不存在，注释是孤儿。
2. MCP 工具全部按 `RiskRead` 处理。`allowed_tools` 能限制暴露范围，但**界面
   不能表达「这个写操作需要审批」**——这是安全边界，不能靠白名单兜底。
3. MCP 连接没有超时。server 卡在启动或不响应时，整个进程会永久挂住。

## 3. 设计决策

| 项 | 决定 | 理由 |
| --- | --- | --- |
| 技能启停持久化 | 写 `<数据目录>/skills.json` | 不污染 TOML；技能目录本身是可移动的数据 |
| MCP 配置写回 | 复用 `SaveProviders` 的外科式写回，新增 `[[mcp]]` 段 | 与现有机制一致，不重新发明 |
| MCP 变更生效 | 立即重连，不重启进程 | 重启对普通用户是不可接受的成本 |
| MCP 工具风险级别 | 新增 `risk` 字段，默认 `read` | 写操作必须能被审批拦下 |
| 技能安装 | **不做**（见 §7） | 从 URL 安装技能是任意代码执行入口 |
| 技能编辑 | **不做**（只读 + 启停） | 编辑器是另一个产品 |

### 3.1 为什么技能启停不写 TOML

技能是「用户数据」，MCP 是「系统配置」。把两者混进同一个文件会导致：

- 用户同步/备份技能目录时，配置跟着漂移
- `SaveProviders` 重写 TOML 时要额外维护第三段，出错面变大

`skills.json` 只存 `{"disabled": ["name", ...]}`，丢了也不影响技能本身可用
（等价于全部启用）。

### 3.2 为什么 MCP 改配置要重连而不是重建整个应用

`connectMCP` 在 `Wire` 里调用一次。重新装配整个应用意味着关数据库、断会话、
丢进行中的轮次——代价太高。正确做法是：

1. 关掉受影响的 `mcp.Client`
2. 从 `tool.Registry` 移除该 server 的工具（按 `mcp.ShortName` 前缀匹配）
3. 按新配置建新 client、连上、注册工具
4. `Service.SetTools(toolReg.Enabled())` 刷新快照

**注意**：`Service.tools` 是快照不是引用（`SetTools` 复制切片），漏了第 4 步
会导致界面显示「已启用」但模型收不到工具。

### 3.3 MCP 工具的风险级别

`[[mcp]]` 增加 `risk = "read" | "write" | "dangerous"`，默认 `read`。

不按工具名猜（「write_file」一定是写？），因为 MCP 工具名是外部 server
定义的，不可信。让用户显式声明，界面给三个选项并说明后果。

## 4. 实现

### 4.1 后端

#### 技能

```
internal/skill/
  catalog.go      SetEnabled 落盘 skills.json；NewCatalog 读取
  state.go        新增：skills.json 的读写
internal/channel/web/
  api_skill.go    新增：列表 / 启停 / 重载
```

接口：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/skills` | 列表：名字、描述、版本、触发词、来源目录、启用状态、参考文件数 |
| `PATCH` | `/api/skills/{name}` | `{"enabled": bool}`，落盘并刷新工具集 |
| `POST` | `/api/skills/reload` | 强制重扫目录（用户刚往目录里放了文件） |

`bootstrap` 需要把 `skillCatalog` 存进 `App`，并加一个 `RefreshTools()` 统一
处理「工具集变了 → 更新 Service 快照」。

#### MCP

```
internal/mcp/
  client.go      补 Healthy() / LastError()；加 Reconnect()
internal/bootstrap/
  mcp.go         新增：MCPManager，持有 clients，支持增删改
  save.go        写回 [[mcp]] 段
internal/channel/web/
  api_mcp.go     新增：列表 / 保存 / 重连 / 测试连接
```

接口：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/mcp` | 列表：alias、传输、命令/URL、启用、风险级别、连接状态、工具数与工具名 |
| `PUT` | `/api/mcp` | 整表保存；返回连接结果（哪些成功、哪些失败及原因） |
| `POST` | `/api/mcp/{alias}/reconnect` | 单体重连 |

#### MCPManager

现在 `connectMCP` 是启动时的一次性函数，要改成能反复调用的管理器：

```go
type MCPManager struct {
    reg     *tool.Registry
    log     *slog.Logger
    svc     *session.Service
    mu      sync.Mutex
    clients map[string]*mcp.Client // alias → client
}

// Apply 让运行中的连接与配置一致：新增的连接、删除的断开、
// 变更的重连。返回每个 alias 的结果。
func (m *MCPManager) Apply(ctx context.Context, servers []config.MCPServer) map[string]error
```

`Apply` 是关键：**幂等**。它比较当前 clients 与目标配置，只动有差异的。
这样保存按钮可以无脑全量提交，不用前端算增量。

### 4.2 前端

新增「技能」与「插件」两个设置页签（`AdminPanel` 加两个 tab）。

#### 技能页

```
技能                                      [重新扫描]
┌────────────────────────────────────────────────┐
│ time-helper                            [开关]  │
│ 一个演示技能，返回当前时间                      │
│ v1 · 触发词：几点、现在时间 · references/ 2 个  │
└────────────────────────────────────────────────┘
（空态）还没有技能。把技能目录放进 <路径> 即可。
        [复制路径]
```

只读列表 + 开关。技能正文可展开预览（L1），但不提供编辑。

#### 插件（MCP）页

```
插件（MCP server）                    [添加] [保存]
┌────────────────────────────────────────────────┐
│ fs        stdio  npx -y @.../filesystem  ● 已连接 │
│ 风险：只读  工具 4 个：read_file, list_dir...   │
│                                   [重连] [删除] │
└────────────────────────────────────────────────┘
```

编辑态字段：alias、传输（下拉）、命令 + 参数（stdio）或 URL（http）、
启用、风险级别（三选一）、允许的工具（逗号分隔，留空=全部）。

保存时一次提交全表，后端 `Apply` 返回逐项结果，失败的项在界面上标红并显示原因——
**不能因为一个 server 连不上就让整次保存失败**。

### 4.3 首次配置向导

向导目前只有「配模型」。技能和 MCP 都不是首次使用的必要条件，**不加进向导**，
避免把「五分钟用起来」变成「十分钟配环境」。技能页与插件页的空态里给出
「怎么加第一个」的说明即可。

## 5. 安全考虑

| 威胁 | 防护 |
| --- | --- |
| 恶意 MCP server 的提示词注入 | 工具描述已带来源标注；返回内容标记外部污点 |
| MCP 写操作未审批 | 新增 `risk` 字段，`write`/`dangerous` 走审批流程 |
| 技能目录被塞入恶意 `SKILL.md` | 技能只加载 Markdown 正文，不执行代码；`requires` 声明的工具不存在时只提示 |
| 用户被诱导添加恶意 server | 界面明示「stdio 会执行本机命令」，添加时二次确认 |

**明确不做**的：从 URL 一键安装技能或 MCP server。这等于把「任意代码执行」
做成一键操作。用户必须自己知道他在装什么。

## 6. 实施顺序

```
① 技能管理（约半天）                    ✅ 完成
   state.go 持久化 → Catalog 读写 → api_skill.go → 前端技能页

② MCP 热管理（约一天）                  ✅ 完成
   Client.Healthy/Reconnect → MCPManager.Apply → save.go 写回
   → api_mcp.go → 前端插件页

③ 文档与测试                            ✅ 完成
   ADR-0021（MCP 热管理与风险分级）
   17/18 号文档更新
```

先做技能：它更简单，且能验证「工具集变更 → Service 快照刷新」这条链路。
MCP 复用同一条链路，风险更低。

### 实施中发现的额外问题

| 问题 | 处理 |
| --- | --- |
| MCP 连接无超时，启动会永久挂住 | 加 20 秒超时，错误文案说明「server 没有响应」 |
| 保存 MCP 时把 `[providers.*]` 一起删了 | `replaceSections` 改为由调用方声明「哪些段归我管」 |
| 配置写回每次累积一个空行 | `renderMCP` 首个段不加前导空行；`joinSection` 处理空 before |
| `Client.Healthy` 只有注释没有方法 | 补 `Healthy` / `LastError` / `Reconnect` |

## 7. 不做

| 项 | 理由 |
| --- | --- |
| 从 URL / 市场安装技能 | 任意代码执行入口；技能是文件，用户自己放 |
| 在线编辑 SKILL.md | 编辑器是另一个产品；用户有文件管理器 |
| 技能依赖自动安装（`requires`） | 会引入包管理器与网络，超出「本地单用户」边界 |
| MCP server 进程守护（崩溃自动重启） | 先观察真实使用；`Apply` 已提供手动重连 |
| 每个 MCP 工具单独开关 | 白名单 `allowed_tools` 已覆盖；细粒度开关会让界面爆炸 |

## 8. 验收

| 项 | 验证 |
| --- | --- |
| 技能列表 | 往 skills/ 放一个新技能，点「重新扫描」，列表出现 |
| 技能启停持久化 | 禁用一个技能 → 重启进程 → 仍是禁用 |
| 技能启停即时生效 | 禁用后模型不再收到该技能目录条目（看上下文检查器） |
| MCP 首次连接 | 添加一个 stdio server，保存后状态为「已连接」，工具数正确 |
| MCP 连接失败不阻断 | 填一个不存在的命令，保存后该项标红报错，其余项正常 |
| MCP 删除清理工具 | 删除 server 后，模型工具清单里不再有它的工具 |
| MCP 重启保持 | 保存后重启进程，配置仍在并自动连接 |
| 风险级别生效 | 把 server 标为 `write`，调用其工具时弹审批 |
| 配置不丢 | 保存 MCP 段后，手写的 `[providers.*]`、注释与其他段原样保留 |
