# ADR-0021：技能启停持久化与 MCP 热管理

> 状态：已定
> 日期：2026-11-10
> 关联：[19-技能与插件管理](../19-技能与插件管理.md) · [ADR-0020](./ADR-0020-API-Key-加密存储.md)

## 背景

技能与 MCP 是白泽区别于普通聊天客户端的地方，但它们此前只能靠手写文件启用：

- 技能启停：`Catalog.SetEnabled` 只改内存，重启即丢
- MCP：只在 `Wire` 时连接一次，增删改要重启进程

这与「打开就能用」的产品断言冲突，也是 v0.2「每天用不别扭」的第一块。

## 决策

### 1. 技能启停写 `skills.json`，不写 TOML

位置：技能目录的**父目录**（默认 `<数据目录>/skills.json`）。

| 理由 | 说明 |
| --- | --- |
| 语义分层 | 技能是用户数据，配置是系统配置 |
| 备份友好 | 用户分享 `skills/` 时不该把「我关掉了哪些」一起带出去 |
| 容错 | 文件丢失/损坏按「全部启用」处理，不会让技能消失 |
| 写回简单 | 不必给 TOML 的外科式写回再维护第三段 |

`SetEnabled` 落盘失败时回滚内存状态：否则界面显示「已禁用」、重启后又是启用。

### 2. MCP 用幂等的 `Apply`，不重建整个应用

重新装配意味着关数据库、断会话、丢进行中的轮次——代价太高。

`MCPManager.Apply(ctx, servers)` 比较当前连接与目标配置：

| 情况 | 动作 |
| --- | --- |
| 新增 | 连接并注册工具 |
| 删除 / 禁用 | 断开并移除工具 |
| 连接参数变化 | 断开重连 |
| 未变且健康 | 不动 |
| 未变但不健康 | 重连 |

**幂等是核心**：界面无脑全量提交，后端只动有差异的部分。前端不必算增量。

`Apply` 末尾必须 `Service.SetTools(reg.Enabled())`：`Service.tools` 是构造时复制的
切片，不刷新等于改了注册表但模型仍拿到旧的。

### 3. MCP 连接必须带超时

20 秒。MCP server 是任意外部进程：可能卡在启动、可能握手后不再响应。
没有超时的话，启动会永远挂住，保存界面也会一直转圈——用户既看不出问题在哪，
也没法取消。

### 4. 新增 `risk` 字段，默认 `read`

`[[mcp]]` 支持 `risk = "read" | "write" | "dangerous"`（留空按 `read`）。

不按工具名猜（`write_file` 一定是写？）——工具名由外部 server 定义，不可信。
让用户显式声明。**未知值一律按 `dangerous` 处理**：填错时宁可多要一次审批，
也不能悄悄降级成免审批。

### 5. 写回按调用方声明的段删除

`replaceSections` 早先按「本包管理的全部段」删除，导致保存 MCP 时把
`[providers.*]` 与 `[route.*]` 一起删了——配置看起来保存成功，用户重启后
模型全没了。现在由调用方传入 `owned` 判定函数：

- `SaveProviders` → `isProviderHeader`
- `SaveMCP` → `isMCPHeader`

## 后果

- 技能启停即时生效，且重启后保持
- MCP 增删改即时生效，失败项逐项报错而不是整体失败
- 写操作类 MCP 工具会走审批
- 配置文件写回幂等：连续保存不改变文件内容

## 不做

| 项 | 理由 |
| --- | --- |
| 从 URL 安装技能 / MCP | 任意代码执行入口 |
| 在线编辑 SKILL.md | 编辑器是另一个产品 |
| MCP 进程守护（崩溃自动重启） | `Apply` 已提供手动重连；先观察真实使用 |
| 每个 MCP 工具单独开关 | 白名单已覆盖；细粒度开关会让界面爆炸 |
