# ADR-0022：耦合治理与分层护栏

> 状态：已定
> 日期：2026-11-13
> 关联：[03-架构纲要](../03-架构纲要.md) §2.3 · [21-测试补强编码计划](../21-测试补强编码计划.md)

## 背景

会话服务把 SQL 写在自己包里，账本直接拿 SQLite 连接，记忆的确认和删除挂在会话服务上，Web 的构造参数是 `*session.Service`，重置数据的回调又把装配层拉去依赖 Web 的类型。

这些都让「换一个存储」或「给渠道做假实现」先要拖进整棵具体类型。Web 生产代码对会话服务有 38 处调用，收成 28 个不同方法。此前把检索工具的帮助文本算了进去，误报成 125 个调用点。

## 决策

### 1. 会话 SQL 只留在 `store/sqlite`

`session.Repository` 由会话包定义，`store/sqlite` 实现。快照的 `prev_snapshot_id`、工具结果的冲突忽略、摘要的读写都在这一侧。

放弃的方案：SQL 留在 `session`，用一个很窄的 `Exec` 接口挡一下。那样领域包仍然知道表名和列，换存储时要改的还是会话包。

### 2. 账本只依赖自己的 `DB` 接口

`cost.DB` 只有 `ExecContext` 和 `QueryContext`。`*sql.DB` 和 `*sqlite.DB` 都满足，账本不 import `infra/sqlite`。

放弃的方案：账本继续持有具体连接。价格和用量不需要迁移、备份或文件路径。

### 3. 记忆管理在 `memory.Admin`

确认、标疑、删除、恢复、改值、画像卡和计数都在 `memory.Admin`。Web 声明自己要用的方法，由这个类型实现。

放弃的方案：这些方法继续挂在 `session.Service` 上。会话服务已经负责轮次和上下文，再承担记忆后台会让两个变化原因缠在一起。

### 4. Web 依赖 `Core`，不依赖具体会话服务

`web.Core` 由四组消费方接口组成：会话与消息、轮次、模型、上下文快照。`*session.Service` 隐式满足它。Web 生产代码调用的就是上面说的 28 个方法。

放弃的方案：渠道参数继续写成 `*session.Service`。那样测试要造出整个服务，渠道也会跟着服务的未使用方法一起变。

`channel/web` 允许 import `provider/registry`。`Core` 的模型方法要写出 `registry.ModelRef`，不引用这个包就写不出签名。协议适配器（`openaicompat`、`anthropic`、`responses`、`sse`）仍然禁止。

`BranchPlan` 导出，字段保持不导出。Web 要在「先返回 turn id」和「后台再跑」之间传递计划，但不该拆开计划里的父节点和叶子。

REPL 仍持有 `*session.Service`。它是进程内调试入口，不经过 HTTP，也没有另一套要替换的实现。

### 5. 重置范围用字符串

`ResetData(ctx, scope string)`。合法值在 Web 里校验成 `sessions` / `knowledge` / `all`，装配层只接收已经校验过的字符串。

放弃的方案：新建一个中立包放这个枚举。它只有三个常量，单独成包不会让依赖更清楚，只会多一个谁都要 import 的地方。也放弃让 `bootstrap` import `channel/web` 来使用 Web 的类型：装配层不该依赖渠道。

## 取舍

分层检查分成两档。传递依赖用 `go list -deps`，直接 import 用 import 列表。`session` 与 `cost` 不得直接 import `infra/sqlite`，违反就失败。`export` 仍然直接依赖 `session`，检查只打印「待治理」，不让命令失败。等导出改成只依赖自己的文档类型，再把这条改成失败。

## 后果

- 会话与账本不再写 SQL，存储细节留在 `store/sqlite` 和满足 `cost.DB` 的连接上
- 记忆后台和会话轮次可以分开测、分开改
- Web 测试可以只实现 `Core` 的一部分；现有测试仍传入具体服务
- 重置回调不再让装配层依赖 Web 类型
- `export → session` 仍是可见的债，不是已经解决的事
