## 1. 范围、角色与术语

### 1.1 范围

白泽是一个**单用户、本地运行**的 AI 个人助理。核心能力：与多个大模型对话、调用工具、长期记忆、检索个人知识库、按技能执行流程，并逐步接入 Web、桌面、CLI、Bot 多种形态。

### 1.2 角色

| 角色 | 说明 |
| --- | --- |
| **使用者**（唯一角色） | 项目主人本人。同时是产品设计者与运维者 |
| 系统内部 | Agent 运行时、Provider 适配器、工具、记忆、RAG、渠道 |

**明确不存在**的角色：管理员、租户、付费用户、审核员、客服。全文需求不得引入与单用户前提冲突的概念。

### 1.3 术语

术语表以[架构纲要 §1.3 全局术语表](./03-架构纲要.md#13-全局术语表)为准，本文不重复定义。

## 2. 需求编号规则

### 2.1 功能需求

`FR-<模块码>-<三位序号>`

| 模块码 | 含义 | 架构参考章节 |
| --- | --- | --- |
| `AGT` | Agent 循环与工具编排 | §4 |
| `CTX` | 上下文工程与可观测 | §5 |
| `MEM` | 记忆系统 | §6 |
| `RAG` | 知识库与检索 | §7 |
| `SKL` | 技能 | §8 |
| `TOL` | 工具协议与 MCP | §9 |
| `PRV` | 模型接入与路由 | §10 |
| `CHN` | 渠道（Web / 桌面 / CLI / Bot） | §2、§14 |
| `UI` | 交互与会话界面 | — |
| `DATA` | 数据、迁移与备份 | §11 |
| `OPS` | 可观测性与成本 | §12 |

### 2.2 非功能需求

`NFR-<类别码>-<三位序号>`

| 类别码 | 含义 |
| --- | --- |
| `PERF` | 性能与资源 |
| `REL` | 可靠性与恢复 |
| `SEC` | 安全 |
| `PRIV` | 隐私 |
| `OBS` | 可观测性 |
| `COMPAT` | 兼容性与分发 |
| `MAINT` | 可维护性 |

### 2.3 优先级

采用 MoSCoW：`M`（Must，当前里程碑必须完成）、`S`（Should，尽力完成）、`C`（Could，有余力再做）、`W`（Won't，本阶段明确不做）。

### 2.4 条目格式

每条 FR 必须包含以下五项，缺一不可：

| 字段 | 说明 |
| --- | --- |
| 编号 | 唯一 |
| 描述 | 一句话说明能力 |
| 优先级 | MoSCoW |
| 验收标准 | 可观察、可测试，避免「体验良好」这类主观表述 |
| 里程碑 | 首个交付该能力的里程碑 |

## 3. 功能需求

### 3.1 FR-AGT Agent 循环与工具编排

| 编号 | 描述 | 优先级 | 验收标准 | 里程碑 |
| --- | --- | --- | --- | --- |
| FR-AGT-001 | 单轮对话可完成「模型推理 → 工具调用 → 结果回填 → 再推理」的完整循环 | M | 一轮内模型连续发起 3 次工具调用并最终给出答复，transcript 中步骤顺序完整可查 | M1 |
| FR-AGT-002 | 同一条助手消息中的多个工具调用并行执行 | M | 一次消息含 2 个独立工具调用时，总耗时不超过串行耗时的 70%；回填顺序与 `tool_use` 出现顺序一致 | M1 |
| FR-AGT-003 | 每轮受步数、墙钟、成本三重预算约束 | M | 步数达 12 时禁用工具并强制收尾；单轮 180s 到期终止并保留已输出内容；预算耗尽给出明确提示 | M1 |
| FR-AGT-004 | 用户可随时中断当前轮次 | M | 点击停止后 1s 内停止流式输出与工具执行；已输出内容落库并标记 `interrupted` | M1 |
| FR-AGT-005 | 中断后的轮次可继续 | S | 对 `interrupted` 轮次点「继续」后，从最后一个未完成步骤恢复，已完成的工具调用不重复执行 | M1 |
| FR-AGT-006 | 进程异常退出后可恢复进行中的轮次 | M | `kill -9` 后重启，会话列表显示该轮为「可恢复」，继续后不重复执行已完成的工具调用 | M1 |
| FR-AGT-007 | 工具调用结果按 `tool_call_id` 幂等缓存 | M | 相同 turn 内同一 call id 重放 3 次，工具实际只执行 1 次 | M1 |
| FR-AGT-008 | 相同工具 + 相同参数重复调用时给出提示 | C | 第 3 次重复时上下文中出现「你已重复调用，请更换策略」提示 | M1 |
| FR-AGT-009 | 错误按统一分类处理并按矩阵重试 | M | 429 自动退避重试并尊重 `Retry-After`；401 不重试且标记 Provider 不健康；已开始流式输出后不再自动重试 | M1 |
| FR-AGT-010 | 支持用户插话的两种模式 | S | 硬中断模式立即开新一轮并注入「用户打断」事实；软排队模式在当前步结束后插入用户消息 | M3 |
| FR-AGT-011 | 工具调用需要人工审批时挂起整轮，并可跨进程重启保留 | M | 审批挂起后重启进程，审批项仍在列表；超时 10 分钟自动 deny 并回填拒绝原因 | M1 |
| FR-AGT-012 | 支持子代理（嵌套 Loop） | C | `task` 工具启动子代理，独立上下文与预算，只回传摘要；深度超过 2 层被拒绝 | M4 |

### 3.2 FR-CTX 上下文工程

| 编号 | 描述 | 优先级 | 验收标准 | 里程碑 |
| --- | --- | --- | --- | --- |
| FR-CTX-001 | 上下文按 8 个语义段组装 | M | 快照中可看到身份、工具技能目录、画像卡、记忆、RAG、历史、当前输入、便签 8 段 | M1 |
| FR-CTX-002 | 稳定前缀在连续多轮内保持不变 | M | 连续 3 轮纯对话中，第 1–3 段内容哈希完全相同（无时间戳等易变内容混入） | M1 |
| FR-CTX-003 | 按段落分配 token 预算并在超限时按固定顺序降级 | M | 构造超限上下文，验证降级顺序为：丢 RAG → 压画像 → 工具结果换句柄 → 滚动摘要 → 丢最老轮次 → 报错 | M1 |
| FR-CTX-004 | 大块工具结果可替换为句柄 | M | 超过阈值的工具结果被替换为「句柄 xxx」，模型调用 `tool_output_read` 能取回原文片段 | M1 |
| FR-CTX-005 | 历史超限时触发结构化滚动摘要 | M | 摘要包含决策与结论、未决问题、实体、偏好、工具产出、用户显式要求 6 个固定部分；最近 8–12 轮原文保留 | M2 |
| FR-CTX-006 | 用户可钉住消息，使其永不参与压缩 | S | 钉住的消息在多次压缩后仍以原文出现在上下文中 | M2 |
| FR-CTX-007 | 跨 Provider 的 token 计数统一 | M | 估算值与实际 usage 偏差在 15% 以内；偏差按 `(provider, model)` 自动校准 | M1 |
| FR-CTX-008 | 每次推理落上下文快照 | M | 任意一轮可查看每段内容、token 数、裁剪原因、缓存断点位置 | M1 |
| FR-CTX-009 | 快照支持与上一轮对比 | S | 界面标出「哪一段变化导致缓存失效」 | M1 |
| FR-CTX-010 | 当前用户输入永不被裁剪 | M | 构造超长输入，验证输入完整保留且降级在其他段落发生 | M1 |
| FR-CTX-011 | 会话历史支持分支，不原地改写 | M | 编辑消息或重新生成产生新分支，旧分支可切换查看，原历史不变 | M3 |

| FR-TOL-011 | MCP 工具白名单与危险工具默认不暴露 | M | 未在白名单中的工具不出现在模型可见列表 | M1 |
| FR-TOL-012 | 工具可声明并行上限 | S | `web_search` 并发上限 2 生效，超出排队 | M1 |
| FR-TOL-013 | 配置中未启用的工具不发给模型 | M | 禁用工具的 schema 不出现在请求中 | M1 |
| FR-TOL-014 | 首期后扩展：文件读写、shell、浏览器自动化 | W | 本阶段不做，留待 M4 之后 | — |

## 5. 数据字典与保留策略

### 5.1 数据分类

| 类别 | 内容 | 存储位置 | 保留策略 |
| --- | --- | --- | --- |
| 会话数据 | 消息、轮次、分支 | SQLite `messages` / `turns` | 永久，用户可删 |
| 记忆数据 | 情节、事实、画像 | SQLite `episodes` / `facts` / `profile_card` | 永久，低优先级归档不删 |
| 知识库 | 文档、chunk、向量、FTS | SQLite + 内容寻址 blob | 随文档删除级联清理 |
| 调用记录 | `llm_calls`、trace、快照 | SQLite | 默认保留 180 天，可配置 |
| 工具输出 | 大结果、附件 | 内容寻址文件目录 | 默认保留 90 天，可配置 |
| 配置与密钥 | 配置、DPAPI 加密文件 | `%APPDATA%\baiyi` | 永久 |

### 5.2 删除语义

- 用户删除会话 → 消息软删除，30 天后由维护任务物理清理。
- 删除文档 → 立即级联删除 chunk、向量、FTS 记录与 blob。
- 删除记忆 → 软删除，可在 30 天内撤销。
- 物理删除只由用户显式触发或维护任务按保留策略执行，且执行前生成清单。

### 5.3 数据目录布局

```
%APPDATA%\baiyi\
├── config.toml
├── secrets.dat            # DPAPI 加密（可选）
├── baiyi.db               # SQLite 主库
├── baiyi.db-wal
├── blobs/                 # 内容寻址：ab/cd/abcdef... 
├── tool_outputs/          # 工具大结果
├── backups/               # 迁移前自动备份
├── logs/
└── skills/                # 用户技能目录
```
