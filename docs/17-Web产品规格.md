## 1. 这个产品是什么

**白泽的 Web 界面——在浏览器里使用个人 AI 助理的唯一入口。**

它不是「把功能清单搬到网页上」。它是用户每天真正会打开的那个东西：发消息、看回答、翻历史、调模型、查花销。

### 1.1 与内核的分工

内核（`session` / `agent` / `contextx` / `memory` / `rag` / `tool`）负责「能不能做」。Web 产品负责「用户知不知道能做、做起来顺不顺、出问题看不看得懂」。

一个典型例子：内核能调用工具、能多步推理，但如果没有审批弹窗、没有「正在调用搜索」的可见反馈，用户只会觉得「它卡了很久然后突然给了个答案」——能力在，产品不在。

### 1.2 与其它产品的关系

| 产品 | 与本产品的关系 |
| --- | --- |
| 桌面产品 | 同一个界面的另一种壳（托盘常驻）。**当前不启动**，见 ADR-0019 |
| CLI 产品 | 共享会话存储。CLI 里聊的话题在 Web 里可见 |
| Bot 产品 | 共享会话存储与工具审批能力 |

**共享的是内核与会话数据，不是界面代码。** 每个产品有自己的界面形态与交互约束。

## 2. 用户

### 2.1 主要用户：项目主人

- 一个人，一台 Windows 11 主力机，可能还有一台笔记本
- 具备开发能力，愿意自己配 API Key、调提示词、写技能
- **不是「给家人用的产品」**——所有设计以「一个人用得爽、改得动、维护得起」为准

### 2.2 用户的时间分布

按真实使用频率排序，这决定了功能优先级：

| 场景 | 频率 | 对产品的要求 |
| --- | --- | --- |
| 随手问一句 | 每天多次 | **打开就能问**，不需要思考配置 |
| 翻上次聊的内容 | 每天 | 会话可搜索、可追溯 |
| 让它查资料/整理文档 | 每周几次 | 工具调用可见、审批不打断思路 |
| 调模型、看花销 | 每周一次 | 数据可信、改配置不用重启 |
| 改配置、加技能 | 每月一次 | 不怕改坏，改坏了能看出来 |

## 3. 成功标准

沿用企划书 §7，但要落到这个产品上：

| 标准 | 在本产品上的具体含义 |
| --- | --- |
| **日常使用率** | 一周 5 天以上主动打开。做到这一点意味着「启动成本」必须接近零 |
| **免解释率** | 打开就是上次的对话，不用重新交代背景 |
| **答案可信度** | 涉及文档的问题有可点击的引用 |
| **可理解性** | 能看到「模型这轮看到了什么、花了多少」 |
| **不卡壳** | 任何失败都有明确原因与下一步，不是一行红字 |

**反面标准**（出现任一条即视为产品未完成）：
- 用户需要读日志才能知道为什么没反应
- 用户需要重启进程才能让配置生效
- 用户不敢改配置，因为怕改坏
- 用户不知道自己花了多少钱

## 4. 功能范围

### 4.1 核心（不做就不是这个产品）

| 能力 | 说明 | 需求 |
| --- | --- | --- |
| 对话 | 流式输出、停止、断线续传 | FR-CHN-002、FR-UI-002 |
| 会话管理 | 新建、重命名、**归档**、删除、搜索 | FR-UI-001 |
| 分支 | 重新生成、编辑后重发、切换分支 | FR-UI-003、FR-CTX-011 |
| 附件 | 图片（视觉输入）、文档（入 RAG） | FR-UI-004 |
| 审批 | 弹窗列出待确认调用，本次/永久允许 | FR-UI-005、FR-TOL-003 |
| 模型配置 | 增删 Provider、测试连通、**填价格** | FR-UI-006、FR-PRV-010/013 |
| 成本 | **本会话** + 今日/本月，数字可核对 | FR-UI-007 |
| 记忆管理 | 查看、编辑、删除、撤销 | FR-UI-009 |
| 知识库管理 | 列表、入库状态、检索测试 | FR-UI-010 |
| 上下文检查器 | 按段展示 token 与裁剪原因，可对比上一轮 | FR-UI-008 |
| 口令 | 开启后访问需登录 | FR-UI-011、NFR-SEC-008 |

### 4.2 产品化（决定「好不好用」，不是「有没有」）

| 能力 | 为什么必须有 |
| --- | --- |
| 配置引导 | 一个 Provider 都没配时，界面要指路而不是卡住 |
| 错误人话化 | `dial tcp: connection refused` 对用户没有意义 |
| 失败可重试 | 网络抖动不该让人重打一遍问题 |
| 401 自动重登 | 会话过期不该让用户对着一行红字发呆 |
| 数据导出 | 「数据属于自己」必须能带走 |
| 首次运行引导 | 从「拿到 exe」到「问出第一句话」的路径要短 |

### 4.3 明确不做（在本产品范围内）

| 项 | 理由 |
| --- | --- |
| 多用户 / 账号体系 | 单用户本地产品，口令只防同机他人 |
| 云同步 | 数据留在本机是核心价值 |
| 移动端 App | 响应式适配即可，不做原生 |
| 插件市场 | 技能是 Markdown 文件，工具走 MCP |
| 插话模式（FR-AGT-010） | 需要 agent 层改造，与 Web 界面无关 |
| 记忆冲突的对话式确认（FR-MEM-009） | 交互设计需单独排期 |
| 查询改写（FR-RAG-013） | C 级优先级 |

## 5. 交互原则

### 5.1 打开即用

冷启动到能发消息，**不需要任何额外操作**。恢复上次会话、上次滚动位置、上次选的模型。

### 5.2 状态永远可见

| 状态 | 用户应该看到 |
| --- | --- |
| 正在生成 | 逐字输出 + 可停止 |
| 调用工具 | 「正在查知识库」而不是空白 |
| 等审批 | 弹窗，说明要做什么、风险多大 |
| 失败 | 中文原因 + 重试按钮 |
| 断线 | 「连接断开，正在重连」而不是静默 |

### 5.3 不打断

审批弹窗只在必要时出现；配置改动不需要重启；长回答不强制滚动到底（用户可能在看中间）。

### 5.4 数据可带走

会话可导出为 Markdown（含分支）；配置是纯文本 TOML；数据库是单个 SQLite 文件。

## 6. 非功能要求

沿用 02 号需求文档，本产品额外强调三条：

| 要求 | 具体值 | 为什么 |
| --- | --- | --- |
| 首屏可交互 | < 2s（本地） | 每天开多次，慢一秒都是负担 |
| 流式首字延迟 | < 1s（不含模型耗时） | 没有首字反馈，用户不知道有没有发出去 |
| 长会话 | 500 条消息不卡顿 | 真实使用半年后就会到这个量级 |
| 模型输出不直达 DOM | 原始 HTML 一律转义，链接只允许安全协议 | 回答经 `{@html}` 注入且无消毒层，模型输出是不可信输入；由 `markdown.test.js` 锁定 |

## 7. 验收：怎么算「做完了」

不是功能清单打勾，而是走一遍真实旅程：

### 7.1 首次使用（全新机器）

1. 拿到 `baiyi.exe`，双击运行
2. 打开浏览器，看到界面
3. **界面告诉我要配模型，并给出入口**
4. 填入 Provider（地址、密钥、模型名），点「测试连接」成功
5. 发第一句话，看到逐字回答
6. 关掉浏览器，重新打开，**对话还在**

### 7.2 日常使用

1. 打开就是上次的对话
2. 发消息 → 看到工具调用 → 审批弹窗 → 允许 → 继续
3. 想看花了多少 → 点成本，**数字与模型服务的账单对得上**
4. 想换个模型 → 顶栏切换，下一轮生效
5. 会话多了 → 能搜索、能归档

### 7.3 出问题时

1. 模型网关挂了 → 看到「主服务不可用，已切换到备用」或明确的失败原因
2. 密钥过期 → 看到「认证失败，请检查 API Key」而不是 `401`
3. 口令会话过期 → **自动回到登录页**，登录后回到原处

### 7.4 数据

1. 导出会话 → 得到完整 Markdown
2. 备份 → 复制一个文件即可
3. 换机器 → 复制数据目录即可

## 8. 与 02 号需求文档的关系

**02 号是整个白泽的需求库**（162 条 FR/NFR），**本文件是 Web 这个产品的完整规格**。

- 本文件引用 02 号的编号，不复制其内容
- 02 号里标 M3/M4 的需求，凡属 Web 产品的，本文件覆盖
- 02 号里属内核的需求（工具、记忆、RAG 的机制），本文件不重复，只描述它们在界面上的呈现
- 本文件新增的产品化要求（配置引导、错误人话化等）不占用 02 号的 FR 编号，它们是「产品要求」而非「系统需求」

## 9. 现状

截至 2026-11-16。三列分开看：**能力存在**不等于**用户找得到**，
找得到也不等于**看得懂**。v0.1–v0.3 解决了第一列，v0.4 完成后两列；
各能力的完成状态由 [18-Web产品路线图](./18-Web产品路线图.md) 独占维护。

| 类别 | 能力存在 | 可发现 | 可理解 |
| --- | --- | --- | --- |
| 核心对话 | 流式、停止、续传、分支、附件、长会话窗口 | ✅ 顶栏与消息内操作 | ✅ 分支说明、断线重连提示 |
| 会话管理 | 新建/重命名/删除/归档/后端搜索分页 | ✅ 会话列表与「更多」菜单 | ✅ |

| 成本 | 今日/本周/本月/全部/本会话、历史按记录时价 | ✅ 用量页 | ✅ 「按记录时价」说明 |
