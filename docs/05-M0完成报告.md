## 过程中发现并修复的真实缺陷

| 缺陷 | 影响 | 修复 |
| --- | --- | --- |
| `ToolResultBlock.Content` 是 `[]Block` 接口，无法 JSON 还原 | 含工具结果的消息落库后读取失败 | 单独实现递归解码 |

## M1 的起点

M0 已经立好的地基，M1 可以直接用：

- `llm` 消息模型含 `ToolUseBlock` / `ToolResultBlock`（已定义，M0 未使用）
- 适配器已能正确解析并交付 `ToolCallReady`（含残缺 JSON 的兜底）
- `llm.Error` 的重试/降级判定已就位（`Retryable()` / `Fallbackable()`）
- 数据库已有 `turns` 表（状态机可直接用）

M1 要新建的：`agent` 包（Loop/状态机/预算/审批）、`contextx` 包（分段组装/预算/快照）、`tool` 包（协议/权限/截断）、`mcp` 包、`skill` 包。

## 已知限制（M0 范围内可接受）

1. **价格未配置**：`config.example.toml` 里价格字段为 0，成本面板显示「价格未配置」。填入实际价格后即可计费（验收项 5 的记账部分已完成，费用计算逻辑已有单测）。
2. **无工具执行**：适配器能解析工具调用并已收集进 `TurnResult.ToolCalls`，但 M0 不执行——执行由 M1 的 Agent Loop 负责。
3. **无上下文组装器**：REPL 直接发送完整历史，没有预算与快照（M1）。
4. **自动重试未接入**：错误分类与重试策略已在 `llm.Error` 定义（`Retryable` / `Fallbackable`），但 REPL 层未接入自动重试循环（M1 的 Agent Loop 负责）。
5. **Agent Loop 尚未独立**：轮次编排目前住在 `session.Service.Ask`，M1 应抽出 `agent` 包，把「消费事件流 → 产出 Step 结果」平移过去，`Ask` 只保留持久化编排。

## 运行日志（A 方案：UI 输出与系统日志分离）

### 两级职责

| 类别 | 去向 | 内容 | 是否落盘 |
| --- | --- | --- | --- |
| **系统日志** | `logx` 产出的 `slog.Logger` | 启动摘要、轮次摘要、模型失败、记账失败、状态更新失败、会话切换 | ✅ 控制台 + JSON 文件 |
| **界面输出** | 渠道自己写 stdout | 对话内容、提示符、token 行、错误提示 | ❌ 仅终端 |

日志文件只记系统事件，不会被聊天内容淹没；需要回放对话用 `messages` 表，不用日志。

### 已落盘的事件

| 级别 | 事件 | 关键字段 |
| --- | --- | --- |
| INFO | 启动 | `data_dir` / `providers` / `chat_route` / `log_level` |
| INFO | 数据库迁移完成 | `applied` |
| INFO | 轮次完成 | `turn` / `session` / `provider` / `model` / `stop` / `in` / `out` / `cached` / `ttft_ms` / `latency_ms` / `cost` |
| INFO | 切换会话 / 新建会话 | `session` |
| WARN | 流中错误 | `turn` / `kind` / `err` / `partial_chars` |
| WARN | 会话标题/时间更新失败 | `session` / `err` |
| ERROR | 模型请求失败 | `turn` / `provider` / `model` / `kind` / `status` / `err` |
| ERROR | 记账失败 | `turn` / `err` |
| ERROR | 轮次状态更新失败 | `turn` / `status` / `err` |
| ERROR | 数据库打开/迁移失败 | `data_dir` / `err` |
| ERROR | 构造 Provider / 初始化账本失败 | `err` |

### 脱敏（FR-OPS-006 / NFR-SEC-001）

`logx` 内所有 handler 外层包了 `redactHandler`：

- 属性名命中 `api_key` / `authorization` / `token` / `secret` / `password` / `cookie` / `credential` 等 → 值替换为 `***`
- 值内嵌的 `Bearer <token>` → 令牌替换，后续内容保留
- URL 查询参数 `?api_key=` / `&key=` / `&token=` → 值替换
- 递归处理 `slog.Group` 嵌套与 `With()` 绑定的属性

实测：debug 级别下日志文件中零密钥泄露。

### 启动失败的两条路径

| 阶段 | 是否落盘 | 用户看到 |
| --- | --- | --- |
| `config.Load` 之前（配置非法、数据目录创建失败） | ❌ logger 尚未建立 | 仅 stderr |
| `logx.New` 之后（数据库、迁移、Provider、账本） | ✅ 已落盘 | stderr + 「详见日志: <路径>」 |

`bootstrap.StartupError` 携带 `LogFile` 字段，`main` 据此决定是否提示日志路径——不会出现「提示了日志但里面没有记录」的误导。

### 过程中修掉的真实缺陷

`slog.LevelDebug` 的值是 `-4`，原 `levelTag` 用 `l >= slog.LevelDebug` 判断，导致所有 INFO 日志被标成 `DBG`。已改为 `l < slog.LevelInfo`。

### 过程中修掉的两个真实缺陷

**1. SSE 注释行被当成事件**
```go
// 之前：注释行执行了 started = true，导致纯注释流在末尾返回空事件
started = true
if strings.HasPrefix(line, ":") { continue }

// 修正：注释判断提前到 started 之前
if strings.HasPrefix(line, ":") { continue }
started = true
```
`ping` 保活事件与调试注释都会被误判，M1 接长连接时会更明显。

**2. `go.mod` 的 go 指令写成补丁版本**（见上表）
